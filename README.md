# Capital OS

Личный инструмент для решений о деньгах. Учёт операций ведётся в MoneyManager; Capital OS импортирует его бэкап и отвечает на вопросы «сколько у меня на самом деле», «куда направить новое поступление» и «что будет, если…». Это PWA, которое работает только на клиенте: финансовые данные не покидают устройство.

## Что умеет

| Экран | Что делает |
|---|---|
| **Импорт** | Читает `.mmbackup` (бинарный префикс + ZIP + SQLite) прямо в браузере. Сверяет баланс каждого счёта с `account_balance` до тиына и показывает расхождения. Неразмеченные категории размечаются в один клик. |
| **Обзор** | Капитал брутто и нетто, обязательства, дебиторка отдельно, ликвидность по датам, платежи на 30 дней, свободные деньги до следующего дохода, предупреждения. |
| **Цели** | Дерево целей. Деньги назначаются целям как метки, а не переводы. Двойной учёт исключён по построению. «Назначено больше, чем есть» — предупреждение с вариантами, цели молча не урезаются. Любое изменение — с причиной и в истории. |
| **Поступление** | Шаг 0 (сколько реально доступно после обязательств и расходов до следующего дохода) → четыре стратегии (Безопасность, Баланс, Ускорение, Своя) → сравнение через симулятор с «ценой выбора» → выбор сохраняется как метки и запись решения. |
| **Прогноз** | Помесячный прогноз на 36 месяцев с дневной проверкой кассовых разрывов, три сценария (базовый, неблагоприятный, благоприятный), плановые события, «что если» для одного решения, альтернативы бок о бок. |
| **Классы** | Мастер вопросов создаёт свой класс и выводит его поведение (базовый, регулярный, нерегулярный, временный, вне прогноза). Любую категорию можно переразметить в один клик. |
| **Настройки** | Ликвидность счетов, ручные счета и депозиты, обязательства, расписание доходов, корректировки, правила классификации, коэффициенты стратегий, сценарии, JSON-бэкап. |

## Запуск

```bash
npm i
npm test          # Vitest: модульные, сценарные и property-тесты
npm run dev       # http://localhost:5173 — режим разработки
npm run app       # сборка + запуск на том же адресе; после первого открытия работает и без командной строки, можно установить как приложение
npm run build     # статическая сборка в dist/ (GitHub Pages, base './')
```

Публикация: при каждом `git push` в `main` GitHub Actions (`.github/workflows/pages.yml`) прогоняет тесты, собирает `dist/` и выкладывает его на GitHub Pages. Публикуется только код приложения: данные пользователя хранятся в браузере каждого устройства и на сервер не попадают. На телефоне: открыть адрес Pages → «Установить приложение» / «На экран Домой»; данные переносятся JSON-бэкапом.

Золотой тест на реальном бэкапе (файл никогда не коммитится):

```bash
CAPITAL_OS_BACKUP=/путь/к/файлу.mmbackup npm test
```

Для демонстрации на фиксированную дату: `http://localhost:5173/?today=2026-11-05`; пример целей из инструкции — с `&demo=1`.

## Архитектура

```
engine/    чистые функции: без DOM, без IndexedDB, без Date.now() — дата всегда параметр
  money.ts         деньги — только целые тиыны; одно место округления (банковское, BigInt)
  import/          свой inflate (RFC 1951), ZIP-ридер, read-only SQLite-ридер, разбор схемы MoneyManager
  classify.ts      операция → ровно один из 24 классов по редактируемым правилам
  ledger.ts        балансы, сверка, капитал, ликвидность, потоки по месяцам, медианы
  obligations.ts   графики рассрочек, сопоставление фактических платежей
  goals.ts         цели, назначения, инварианты двойного учёта
  ladder.ts        шаг 0 и «лестница» распределения, параметризованная стратегией
  simulate.ts      помесячный симулятор + дневные разрывы, сценарии, «что если»
  allocate.ts      сравнение стратегий через симулятор, объединение, «цена выбора»
  overview.ts, goals-view.ts, plan.ts — модели экранов из состояния приложения
  setup.ts         шаги первичной настройки («Первые шаги») и их готовность
  installment-detect.ts  рассрочки из операций: находки, остаток по сроку/дате, проверка заведённых
  state.ts         состояние и детерминированный JSON-бэкап
app/       UI на vanilla TypeScript + IndexedDB; движок вызывается только через engine/index.ts
tests/     unit/, scenarios/ (ситуации из спецификации), fixtures/ (синтетические данные)
docs/      DECISIONS.md — все решения с обоснованием, BLOCKERS.md — ограничения среды
```

**Жёсткие правила движка.** Нет float в суммах. Нет скрытых констант: коэффициенты стратегий и сценариев лежат в настройках. Функции детерминированы, при равенстве порядок задаётся `id`. Каждый расчёт возвращает `explanation` — список шагов, из которого строится текст «Как посчитано». Каждое число на экране воспроизводится из входных данных.

## Ключевые алгоритмы

**Шаг 0.** `Доступно = Поступление − R1 − R2`, где R1 — платежи по обязательствам до следующего дохода, R2 — медиана базовых расходов × дни / (365/12). Свободные деньги на счетах сначала покрывают R1, затем R2 (DECISIONS D41). Если доступно ≤ 0, стратегии не строятся: показывается непокрытый платёж, дефицит и варианты действий.

**Лестница.** Уровень 1 — резерв до цели стратегии. Уровень 2 — ежемесячные минимумы целей со сроком `⌈(min − есть) / мес.⌉` с округлением вверх до 100 ₸. Порядок: обязательства → ранний срок → важность → id. Уровень 3 — остаток по правилу стратегии: веса `важность × срочность` с потолками, методом наибольших остатков в тиынах.

**Классы с поведением.** Класс — экономическая роль операции; поведение говорит, как его считать. Базовые классы задают резерв и запас до дохода. Регулярные продлеваются в прогноз медианой, нерегулярные — годовой суммой / 12 (пока истории меньше года — оценкой пользователя / 12), временные — до своей даты.

**Симулятор.** Помесячный шаг с дневным проходом: доходы → события → платежи → расходы → проценты → покрытие минуса из доступных вкладов → проверка разрыва. Проценты по вкладу недоступны до даты разблокировки. Назначения целям — метки, поэтому капитал у всех стратегий одинаков, а различаются даты целей и резерв. Жизнь пользователя (переезд, аренда, работа) задаётся событиями, а не кодом.

## Тестирование

- **286 тестов**, покрытие `engine/` — более 95% строк.
- **Сценарные тесты** ситуаций 1–9 из спецификации. Ожидаемые числа посчитаны вручную до реализации, вплоть до даты кассового разрыва и тиына процентов.
- **Property-тест двойного учёта**: 300 случайных последовательностей «назначить / снять / потратить / перевести / перенести» проверяют инварианты после каждого шага. Сид воспроизводим: `PROP_SEED=…`.
- **Стресс-тест SQLite-ридера** на «андроидной» базе (тысячи строк, freelist, overflow, auto_vacuum, страницы 1–4 КБ) сравнивается построчно с настоящим SQLite.
- **Тест детерминизма**: 100 прогонов симулятора дают байт-в-байт одинаковый результат.

## Статус

Этапы 1–3 из 5 готовы: ядро, цели, распределение и прогноз. Этап 4 (предупреждения, журнал решений, снимки прогнозов, экспорт для ИИ) и этап 5 (план против факта) ещё не начаты.
