# Переделка экранов (D96) — спецификация

Источник: документ «Capital OS — план новых экранов» (03.11.2026), правки и решения владельца там же.
Принцип: новый первый слой поверх того же движка. Всё старое (стратегии A–D, сценарии, коэффициенты,
«Как посчитано», разметка классами) не удаляется — уходит во второй слой «Подробнее».

## Модель (дополнения, все поля необязательные — старые бэкапы читаются)

| Где | Поле | Смысл |
|---|---|---|
| `AccountSettings` | `kind?: 'spend' \| 'savings'` | «для трат» (по умолчанию) или «копилка» |
| `Goal` | `order?: number` | порядок в списке (перетаскивание); вместо важности 1–5 |
| `Goal` | `folder?: true`, `splitEqually?: true` | папка вместо подцелей; «делить поровну» внутри папки |
| `TargetRule` | `basis?: 'essential' \| 'all'` | подушка: «обязательное + жизнь» / «все обычные траты»; нет правила — «своя сумма» |
| `GoalFunding` | `pending?: true` | «Отложил», но перевод на копилку в бэкапе ещё не найден |
| `CategoryRule` | `auto?: true` | правило поставлено автоматически по названию категории |
| `Settings` | `forecastViewMonths?`, `showDetails?`, `dismissedIncomes?` | срок у числа прогноза; «Сразу показывать подробности»; «это не доход» |
| `Settings` | `simpleMigrated?: true` | перенос на новую модель сделан |
| `StrategyId` | `'S'` «Простая» | правила распределения нового экрана; она же стратегия плана для прогноза |

## Числа

- **Можно тратить до <след. доход>** = Σ счетов «для трат», доступных сегодня − отложенное, но не переведённое
  (назначения целям на счетах «для трат») − платежи по долгам и рассрочкам до дохода.
  **≈ в день** = это ÷ дней до дохода. **Обычно уходит** = (медиана «повседневного» + «регулярного») ÷ 30,4.
- **На руках всего** = Σ всех учитываемых счетов, включая депозиты с датой; строкой «из них N в копилках»
  и «N на депозите до …».
- **Подушка**: `essential` = месяцы × (повседневное + платежи по долгам в месяц); `all` = месяцы × (повседневное +
  регулярное + платежи); «своя сумма» — как задано. Срок в месяцах — отдельно (по умолчанию 3).
- **Распределение «Пришли деньги» (стратегия S)**: шаг 0 как раньше (платежи до дохода и обычные траты до дохода,
  с покрытием свободными деньгами), но обычные траты = повседневное + регулярное. Затем: 1) подушка (до суммы) и
  цели со сроком (сколько нужно в этом месяце) — по порядку списка; подушка по умолчанию первая, но двигается (D100);
  2) цели без срока — по порядку,
  каждая до суммы; в папке «поровну» — поровну между целями папки. Остаток — на жизнь.
- **Вердикт цели со сроком**: месяц достижения по прогнозу (стратегия S) ≤ срока → «успеваешь — откладывай ≈ X в месяц»
  (X = осталось ÷ месяцев до срока); иначе «не успеваешь — нужно ещё Y в месяц, или сдвинь на <месяц из прогноза>»,
  Y = (сумма − прогноз накопленного к сроку) ÷ месяцев до срока.
- **Запас прочности** = прогноз без доходов: месяцев до первого кассового разрыва («хватит на N месяцев (до <месяц>)»).

## Поведение

- «Отложил» — метки на счёте, куда пришли деньги, с `pending`. После следующего импорта: перевод с этого счёта
  на копилку → метки переезжают на копилку; перевода нет, а бэкап новее даты «Отложил» → строка
  «Отложил N, но перевода на копилку в бэкапе нет» в «Требует внимания».
- Новый регулярный доход в бэкапе (категория дохода в ≥ 2 месяцах из последних трёх, не заведена) → одна строка
  на Обзоре «Похоже, у тебя новый доход: <название> ≈ N, <день>-го. Добавить? / Это не доход».
- Импорт: неразмеченные категории размечаются сами по названию (`auto`), неизвестные — «прочее».
  4 корзины трат = поведение класса: повседневное (base), регулярное (regular), разовое (irregular/temporary/excluded),
  долги и рассрочки (installment). Поправить — «Данные → Раскладка трат».
- После D100: «Пришли деньги» сначала спрашивает «Помочь распределить?» / «Уже распределил»; прогноз — полгода и год;
  категории без названия называются по иконке MoneyManager и переименовываются в «Раскладке трат».
- Первый запуск после импорта: 3 шага (доходы, копилки, на что копишь), у каждого «Пропустить».

## Перенос старых данных (один раз, `simpleMigrated`)

Перед переносом копия исходного состояния — в браузере под ключом `state.before-simple`.
Счёт с привязкой к цели, не «сразу» по доступности или с названием про копилку/вклад/депозит → копилка; остальные →
для трат. Корневая цель-резерв → подушка (`basis: 'essential'`, если было правило). Цель с подцелями → папка.
Порядок = прежний (важность, затем id). Комфортная сумма убирается. Стратегия плана → S. Доходы, рассрочки,
назначения, история и ручные правила разметки — без изменений.
