# Для ИИ-ассистента: с чего начать

Capital OS — PWA к MoneyManager (Android). Загружает бэкап `.mmbackup` и отвечает: сколько можно тратить до следующих денег, сколько отложить из пришедших, успеваю ли к целям, что будет, если… Всё на клиенте, без серверов и runtime-зависимостей.

## Порядок чтения

1. `README.md` — запуск и состав проекта.
2. `docs/simplify/spec.md` — что реализовано сейчас и как считаются числа.
3. `docs/DECISIONS.md` — почему так (D1–D147). Новое решение — следующий номер.
4. `docs/simplify/README.md` — цель: приложение понятно без финансовой подготовки.
5. `docs/BLOCKERS.md` — ограничения среды.

## Устройство

- `engine/` — чистые функции, деньги в целых тиынах, дата — параметр. Новый слой простых экранов — `engine/simple.ts`; распределение — `engine/ladder.ts` (стратегия «S» — по списку целей).
- `engine/position/` — «Положение» v4: показатели, направления, ограничители, диапазон, уровни L1–L5 (в коде; на экране — названия и «Ступень N из 5», условия-факты `gateLevel`, D151), runway, долговая спираль, независимость (`independence.ts`, в т. ч. личный сценарий), нормализаторы вводов (`inputs.ts`); `view.ts::positionViewOf(state, today)` — вся модель экрана одной чистой функцией. Запас и «Из А в Б» — `engine/reserve.ts`, `engine/roadmap.ts`. Прогноз на дату и «Расчёт по шагам» — `engine/forecast-steps.ts` (срок «сегодня + N месяцев»; помесячный ряд остаётся для целей и «Положения»).
- `app/` — интерфейс на vanilla TS (`h()`), экраны в `app/screens/`, справка — `app/screens/help.ts` и `app/help-text.ts`.
- `tests/support/position-profiles.ts` — синтетические профили «Положения» (фикстуры тестов и состояния `pos-*` для `scripts/ui-states.ts`).
- `tests/` — модульные и сценарные тесты; фикстуры синтетические (`tests/fixtures/`).

## Правила (обязательные)

1. **Push в `main` сразу публикует сайт.** Работай в ветке, сливай через pull request.
2. **Математику `engine/` не меняй без согласия владельца.** Если меняется ожидание теста — запись в `docs/DECISIONS.md`.
3. **Никаких личных данных**: ни реального бэкапа, ни чужих сумм, ни целей конкретного человека — ни в коде, ни в документах, ни в тестах. Только синтетика.
4. Не добавляй runtime-зависимости и внешние запросы.
5. **После любого изменения интерфейса обновляй справку** (`app/screens/help.ts`, `app/help-text.ts`).
6. Интерфейс — по-русски, на «ты», коротко; без внутренних терминов (R1, коды типов, «горизонт» и т. п.). Не оставляй полумер: если переименовываешь понятие — везде сразу.
7. Решения о направлении принимает владелец. Не уверен — задай один короткий вопрос.
8. **Работа не должна жить только в песочнице.** Песочница сессии не сохраняется: незакоммиченный код пропадает (так уже терялись T01–T02). После каждой завершённой задачи или шага — коммит в рабочую ветку и `git push origin <ветка>` (не в `main`). Слияние в `main` — только по просьбе владельца и через pull request. Эталонные фикстуры, снятые со скриптов проб, коммитятся вместе с тестами.

## Проверки перед pull request

```
npm test                      # или: bun test
npm run typecheck             # или: npx tsc --noEmit -p tsconfig.local.json
PORT=5199 bun scripts/dev-server.ts &
bun scripts/ui-check.ts       # все экраны, светлая и тёмная тема (запускать одну, без других проверок: при нагрузке ловит ложный «контраст 1.00»)
bun scripts/storage-check.ts  # защита данных; в т. ч. настройки и активы «Положения» (T16)
bun scripts/ui-inputs.ts      # вводы «Положения»: «О тебе», ручной актив, ошибки форм (T16)
```

Все должны проходить.
