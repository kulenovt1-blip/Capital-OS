# Блокеры

Что мешало сделать по инструкции и какой обходной вариант выбран. Каждый пункт: проблема → обход → что нужно от тебя.

## B1. npm-реестр недоступен из рабочей среды

**Проблема.** В облачной среде, где шла ночная работа, `registry.npmjs.org` закрыт политикой сети (CONNECT 403). Поставить `vitest`, `vite`, `sql.js`, `fflate`, `fast-check`, `idb`, `preact` не удалось.

**Обход.**
- Движок сделан **без runtime-зависимостей**: свой распаковщик DEFLATE (`engine/import/inflate.ts`), свой ZIP-ридер (`engine/import/zip.ts`) и свой read-only ридер формата SQLite (`engine/import/sqlite.ts`). Всё проверено тестами против эталонов (zlib и настоящий SQLite).
- Тесты написаны на API Vitest (`import { describe, it, expect } from 'vitest'`). Ночью их гонял Bun 1.4 (`bun test`), он понимает этот импорт. У тебя `npm test` запустит настоящий Vitest.
- Property-тесты сделаны на маленьком своём генераторе с сидом (`tests/support/prop.ts`) вместо `fast-check`.
- UI сделан на vanilla TypeScript без фреймворка; в `package.json` объявлен `vite` для `npm run dev`. Ночью сборку проверял `bun build`, а сами экраны — скриншотами в Chromium.
- IndexedDB — тонкая обёртка в `app/storage.ts` вместо `idb`.

**Что нужно от тебя.** Выполнить `npm i && npm test && npm run dev`. Если Vitest или Vite на чём-то споткнутся, это первое, что нужно чинить: у меня они не запускались, хотя код писался под их API.

## B2. Нет реального бэкапа MoneyManager — ✅ снято 28.10

**Итог.** Золотой тест прогнан на реальном бэкапе на машине пользователя: все счета сошлись с `account_balance` до тиына. Сам бэкап в репозиторий не попадает (`.gitignore`).

**Проблема.** Файл `.mmbackup` не передан, золотой тест на реальных данных не прогнан. Критерий готовности этапа 1 («реальный бэкап сходится до тиына») **формально не проверен**.

**Обход.** Синтетический бэкап `tests/fixtures/synthetic.mmbackup` собирается скриптом `scripts/make-fixtures.ts` строго по схеме из инструкции §3.1 (8-байтовый префикс + ZIP + `MyFinance.db`). Эталонные `account_balance` в нём посчитаны SQL-запросами в самом скрипте, независимо от кода движка. Плюс фикстура с намеренной ошибкой в 1 тиын, чтобы проверить, что расхождение ловится.

**Что нужно от тебя.**
```
CAPITAL_OS_BACKUP=/полный/путь/к/файлу.mmbackup npm test
```
Тест `tests/unit/golden-real.test.ts` импортирует файл и проверяет сходимость по каждому счёту. Если не сойдётся — смотри B3.

## B3. Неочевидные места формата, которые я не мог проверить

Сделаны по букве инструкции, все вынесены в одно место (`engine/import/mmbackup.ts`, константа `MM_SCHEMA`), чтобы поправить за минуту:
- значения `sync_link.otherType` для переводов приняты буквально: `FromAccount` / `ToAccount`;
- `account_balance.uid` считается равным `account.uid`;
- суммы в `transaction.amountInDefaultCurrency` считаются положительными, знак задаёт `type`. Если встретится отрицательная сумма, импорт берёт модуль и пишет предупреждение;
- связи читаются в обе стороны (`Transaction→Account` и `Account→Transaction`), на случай если направление в реальном файле обратное.

Если золотой тест не сойдётся, в отчёте сверки по каждому счёту видно: расчёт, эталон, разница и число операций. По этому сразу понятно, какое из допущений неверно.

## B1 (дополнение, сессия 2). Реестр npm по-прежнему закрыт

Во второй сессии `registry.npmjs.org` отвечал 403 через прокси среды (политика). Обходить не стал.
- **Типы** проверены `tsc` 6.0.2 из локального кэша npm (`tsconfig.local.json`: `engine/` + `app/`) — 0 ошибок. Тесты типами не проверялись: нет `@types/node`. У тебя `npm run typecheck` проверит всё; если `@types/node` не знает `node:sqlite`, ошибка будет только в `tests/unit/sqlite-stress.test.ts` (подними `@types/node` до свежей 22.x).
- **Тесты** гонялись Bun 1.4 (`bun test`): 203 зелёных + 1 пропущен (золотой тест без файла). Под Vitest не запускались. Bun-специфичных API в тестах нет, только `vitest`-импорт и `node:*`.
- **UI** проверялся в настоящем Chromium (Playwright) через запасной dev-сервер на Bun (`scripts/dev-server.ts`), не через Vite. Сценарии: импорт → разметка → цели → назначение → превышение после трат → поступление → выбор стратегии → прогноз → «что если». Ошибок в консоли нет.
- **Графики**: Chart.js/uPlot поставить нельзя → график капитала нарисован на SVG без библиотек (`app/chart.ts`): одна ось, легенда, подписи на концах, перекрестие с подсказкой, таблица значений рядом.

## B5. Стресс-тест SQLite требует Node ≥ 22.5

`tests/unit/sqlite-stress.test.ts` строит базу через `node:sqlite`. На более старом Node он пропускается, а не падает.

## B6. Этап 3 «правдоподобно на реальных данных» не проверен

Критерий готовности этапа 3 включает «сравнение стратегий на реальных данных выглядит правдоподобно для пользователя» — без твоего бэкапа это не проверить. На синтетических данных поведение разумное: при поступлении, которое целиком уходит в недобранный резерв, все стратегии честно сводятся к одной с объяснением.

## B7. Первый прогон под Vitest (28.10, у пользователя, Node 24)

197 пройдено, 0 упало. Но стресс-тест SQLite (6 тестов) тихо пропустился: Vitest 2.1 загружает модули через свой загрузчик, который не знает `node:sqlite` как встроенный модуль. Исправлено: модуль берётся через `process.getBuiltinModule`. Добавлен тест-сторож — на Node ≥ 22.5 недоступный `node:sqlite` теперь ошибка, а не пропуск.
